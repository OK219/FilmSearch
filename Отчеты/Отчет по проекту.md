## Доменная область
Приложение FilmSearch представляет из себя сайт, где пользоваетли могут искать фильмы и оставлять к ним рецензии. (урезанный Кинопоиск вообщем)
Поиск фильмов осуществляется по подстроке, так же есть фильтры по дате выхода и сортировка по рейтингу, дате, названию.
Фильмы может добавлять и удалять только админ через форму доступную только ему

## Основные сущности
Фильм, отзыв, жанр, пользователь. У фильма может быть только один жанр в текущей реализации, много отзывов. Пользователь может оставить только один отзыв к одному фильму и сам же его удалить.


## Стек 
C# (Asp .Net) + PostgreSql (Entity Framework для работы с ним) + S3 хранилище (Yandex Cloud)
В хранилище находятся постеры к фильмам, при добавлении фильма бек сохраняет постер в S3 и записывает ссылку на него в бд а после фронт сам подтягивает постеры.

## Соответствие факторам

# 1 Кодовая база
Приложение одно и находится в одном репозитории (в настоящий момент архиве); разных контуров пока нет, но если появятся, то не вижу проблем использовать эту же базу

# 2 Зависимости
Приложение изолировано в контейнере и запускается через docker compose up. Зависимости приложения можно посмотреть в csproj (всякие нугет пакеты), а так же в докер файлах можно увидеть утилиты необходимые для проведения миграций.

# 3 Конфигурация

В приложеении нет захардкоженных настроек, все указывается в compose.yaml, а секрктные настройки хранятся в .env (пример можно псмотреть  в .env.example)

# 4 Сторонние сервисы

Все данные для подключения к постгресу и S3 находятся в конфигах, можно спокойно заменить локальный постгрес из того же компоуза на облачный постгрес, а яндексовский S3 на амазоновзский

# 5 Build, release, run

Этот фактор не особо вяжется с локальной разработкой, наверно уже в домашке с кубером можно над ним думать или это вообще в сторону CI/CD уже

# 6 Процессы

Приложение не имеет состояния, настолько, что вход в профиль при перезапуске в приложение сбрасывается))

# 7 Привязка портов

В компоузе пробрасываются порты приложенияя, к приложению можно обратиться по конкретному порту

# 8 Параллелизм

Опять же не про локальную разработку, но горизонтальное масштабирование не должно быть проблемой

# 9 Утилизируемость

Все данные необходимые для корректной работы хранятся в бд и S3, поэтому при падении приложения потерь не происходит. Старт быстрый

# 10 Паритет разработки и продакшена

С момента первого фактора разных контуров не появилось))

# 11 Логирование

Все логи пишутся в консоль, а дальше их можно глядеть через логи докера

# 12 Административные задачи

Вынес проведение миграции в отдельный одноразовый этап при поднятии компоуза
